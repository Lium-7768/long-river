## 0. 结论速览（先看这个）

| 排名 | 数据源 | 可行度 | 关联键 | 预计可补 |
|---|---|---|---|---|
| ★1 | **CBDB 官方最新 SQLite（HuggingFace）** | 极高（直接下载） | `cbdb_id` ↔ `persons.cbdb_id` | 全库增量/新字段 + Wikidata Q-ID 桥 |
| ★2 | **CHGIS / TGAZ 历史地名 API** | 极高（已验证 JSON） | 地名汉字 + 年份 → 坐标 | `addr_geo` 15,558 → 可扩到 13.5 万条历史地名 |
| ★3 | **Wikidata SPARQL** | 高（已验证） | 姓名+生卒 / 已有 Wikidata 来源标记 | 生卒/职业/籍贯纠错，约 40 万人物已有来源 |

## 1. CHGIS（中国历史地理信息系统，哈佛/复旦）

- **URL**
  - 项目主页：https://chgis.fas.harvard.edu/
  - 下载页：https://chgis.fas.harvard.edu/data/chgis （V1–V6，静态站点，旧版链接已断）
  - 数据集库（Harvard Dataverse）：https://doi.org/10.7910/DVN/JX4KSQ （CHGIS V3 Relational Database）
  - **TGAZ 地名 API（当前可用主入口）**：https://chgis.hudci.org/tgaz/ （文档 https://chgis.hudci.org/tgw/ ）
  - 旧镜像：http://maps.cga.harvard.edu/tgaz/ （301 跳转到 chgis.hudci.org）
- **许可**：CHGIS 数据免费（"a free database of placenames"），Dataverse 条目未标 SPDX；TGAZ 由 Mellon/NSF 资助，接口为 **READ-ONLY 开放访问**。引用要求：CHGIS, Harvard & Fudan。**建议正式使用前邮件 CGA 确认再分发条款**（Dataverse license 字段为 None）。
- **数据格式**：官方库 `v3_mysql_distrib.zip`（16.8 MB，MySQL dump）/ `v3_chgis_database.mdb`（52 MB）；TGAZ API 返回 **JSON / XML（默认）/ HTML**。
- **规模**：CHGIS V3 覆盖全国历代县级及以上行政单元；TGAZ 文档自称约 **135,744 条地名记录**（多条 = 同一地名在不同朝代的**时序版本**）。
- **可否程序化获取**：**可以，且已验证**。RESTful 接口，无需鉴权，CORS 全开。
- **关联键（关键）**：**地名汉字（name）+ 年份（yr）**。我们的 `addr_geo.name` 为纯汉字（如"苏州/开封/会宁府/辽阳"），与 TGAZ `name` 字段直接匹配；TGAZ 每条记录带 `years`（起止年），可与我们 `addr_geo.first_year/last_year` 对齐做**时序消歧**。
- **样本验证（已跑通）**：

  ```bash
  curl 'https://chgis.hudci.org/tgaz/placename?n=苏州&fmt=json'
  ```
  返回 21 条"苏州"的历代记录，字段样例：
  ```json
  {"sys_id":"hvd_32418","uri":"https://chgis.hudci.org/tgaz/placename/hvd_32418",
   "name":"苏州","transcription":"Su Zhou","years":"589 ~ 590",
   "parent sys_id":"hvd_113617","parent name":"隋 (Sui)",
   "feature type":"州 (zhou)","object type":"POINT",
   "xy coordinates":"120.61862, 31.31271","data source":"CHGIS"}
  ```
  带年份筛选 `&yr=1000` 可精确取"公元 1000 年时"的行政区：
  ```bash
  curl 'https://chgis.hudci.org/tgaz/placename?n=苏州&yr=1000&fmt=json'
  # -> 2 条：苏州 758~1112 / 939~1112，坐标 120.61862,31.31271
  ```
  命中率抽样（我们的地名 → TGAZ 命中数）：开封 12、临安 15、洛阳 16、建康 7、会宁府 1、辽阳 8。
- **与我们数据的结合点**：
  - `addr_geo`（15,558 条，其中 10,990 条已有 `chgis` 整数 ID）——**注意：该 `chgis` 字段正是 CHGIS 的 sys_id**（如"满城"=44747、"肇州"=120482）。这意味着**我们已经用了 CHGIS，只是只覆盖了 1.1 万条**，可用 TGAZ 反向把剩余 4,568 条 + 新增地名补齐坐标。
  - `addr_belongs`（隶属层级）可借 TGAZ 的 `parent sys_id / parent name` 补全历代隶属链。
- **可行度**：**极高**。唯一注意事项：TGAZ 每条地名有多个时序版本，合并时务必按年份区间挑选，避免坐标错位。
- **建议**：写一个 ETL，遍历 `addr_geo` 的 6,935 个不同地名 → 调 TGAZ → 按 `first_year/last_year` 选最近版本 → 回填 `lon/lat/chgis`。优先做宋代（song-w / song-e / song-s）地名。

## 2. Wikidata / DBpedia

- **URL**
  - Wikidata SPARQL 端点：https://query.wikidata.org/sparql （GET/POST，`Accept: application/sparql-results+json`）
  - 官网：https://www.wikidata.org/
  - DBpedia：https://dbpedia.org/sparql （中文库覆盖远弱于 Wikidata，不推荐主用）
- **许可**：**CC0**（Wikidata 主命名空间数据均为公有领域贡献，无版权限制）。DBpedia 为 CC BY-SA。
- **数据格式**：SPARQL JSON/XML，或实体 JSON（`Special:EntityData/Qxxx.json`）。
- **规模**（实测查询）：
  - `P27 ∈ {Q29520 中国, Q148 中华民国, Q8733 …}` 且有生年的人物：**80,133**；
  - 其中带生+卒年+职业者，抽样正常返回（含晋怀帝、杨坚、华佗等）。
  - 我们库中**已有 404,350 人**（占 666,955 的 61%）的 `sources` 字段含"維基數據 (Wikidata)"——说明**我们此前已用过 Wikidata**。
- **可否程序化获取**：**可以**。SPARQL 端点公开、免鉴权（限 1 req/s、需合理 UA）。
- **关联键**：
  1. **已有桥**：`persons.sources` 里的 Wikidata 标记（但只存了来源名，未存 Q-ID，需要补一张 `person → QID` 映射表）；
  2. **模糊键**：中文姓名 + 生年/卒年（P569/P570）联合匹配，可校验我们 60,753 条生年、72,147 条卒年；
  3. **DILA / CBDB 桥**：见 §4，DILA 与 CBDB 都带 Wikidata Q-ID（如慧能 = Q345012）。
- **验证样本**：
  ```bash
  curl -G 'https://query.wikidata.org/sparql' \
    --data-urlencode 'query=SELECT ?p ?pLabel ?b ?d WHERE {?p wdt:P27 wd:Q29520; wdt:P569 ?b; wdt:P570 ?d. FILTER(YEAR(?b)<1912) SERVICE wikibase:label {bd:serviceParam wikibase:language "zh".}} LIMIT 50' \
    -H 'Accept: application/sparql-results+json'
  ```
- **可补内容**：生/卒精确日期（我们多为年份）、职业 P106、籍贯 P19、画像 P18、百科链接 sitelinks。
- **可行度**：**高**。缺点：Wikidata 古典人物（尤其中古）覆盖稀疏，且姓名歧义大（需 Q-ID 精确桥）。
- **建议**：不要指望大规模补人物；**定位为"生卒/职业纠错 + 给 40 万已有 Wikidata 来源者补 Q-ID"**。配合 §4 的 DILA/CBDB Q-ID 桥，可建 `person ↔ QID` 双向外链。

## 3. DILA 佛学/道教人物库（法鼓文理学院，含 CBETA 关联）

- **URL**：https://authority.dila.edu.tw/ （人名規範資料庫 https://authority.dila.edu.tw/person/ ；
  地名規範資料庫 https://authority.dila.edu.tw/place/ ；时间规范库等）
- **许可**：学术开放访问（CC 类，需核实具体条款；法鼓 DILA 数据一般 CC BY-SA）。**无公开 REST API**。
- **数据格式**：**HTML 网页（frameset + 表单提交）**，无 JSON 接口（试过 `?format=json`、`/api/` 均 404）。
- **规模**：地名规范库自称 **59,376 条地名**；人名库据公开资料约数万人（僧侣/道士为主，含 CBETA 引证）。
- **可否程序化获取**：**部分可**。搜索页 `person/search.php?per=<名字>&isLikeSearch=1` 返回 HTML 结果表，可解析；但详情页 id 模式需逆向、且无批量导出。**建议人工抽样 + 少量爬取，或走离线数据许可申请**。
- **关联键（重点，已实测）**：
  - DILA 人名的 `SameAs` 区块同时给出 **Wikidata Q-ID + CBDB personid + CBETA 卷号**；
  - 实测：`search.php?aid=A001719`（慧能）返回 `CBDB：cbdbapi/person.php?id=0094985`，
    而该 CBDB id `0094985` 正是我们库中 `persons.cbdb_id=94985`（`shihui-94985` 释慧能，638–713，唐）。
  - **链路成立：DILA A-id → CBDB personid → 我们 `persons.cbdb_id`**。
- **可补内容**（慧能页实测字段）：别名（六祖/大鑑禪師/曹溪…）、生卒精确日期 + **纪年原文**（"生於：唐,太宗,貞觀,十二年,二月,初八日"）、出生地（PL 地名 ID）、宗派（南宗）、是否僧人、**师徒关系（老师/弟子，带 CBETA 引证）**、著作（作译资料）。
  → 对我们**最缺的僧侣/道士字段**（宗派、僧俗、师承）是直接补充。
- **可行度**：**中**。数据质量极高（逐条带 CBETA 原文引证），但获取成本高（网页、无 API）。适合**定向补**：先锁定我们库中的僧侣（名字含"释"/僧/道士），再逐条查 DILA。
- **建议**：① 用它给我们的僧侣补 `宗派/师徒/生卒精确日`；② 用其 `SameAs` 区块给 `persons` 建 Wikidata Q-ID + CBETA 引用外链。

## 4. 中国哲学书电子化计划 (ctext.org)

- **URL**：https://ctext.org/ · API 文档页 https://ctext.org/tools/api （需订阅）
- **许可 / 条款（关键）**：**明确禁止爬取**。官方声明原文：
  > "Attention researchers: if you're trying to do web scraping for a research project, please ask your institution to subscribe… Web scraping of this site is in violation of our terms of service… the system identifies scrapers, it will intermittently intentionally return corrupted data."
  - API 请求实测返回 `ERR_REQUIRES_AUTHENTICATION`（需注册 IP 或 API key）。
  - `robots.txt` 对 GPTBot/ChatGPT-User/Amazonbot 等一律 `Disallow: /`。
- **数据格式**：订阅后 JSON API + Python 模块。
- **可否程序化获取**：**否（除非机构订阅）**。没有任何合法的免费批量通道。
- **关联键**：无结构化人物字段，正文全文匹配人物名 `persons.name`（若订阅可用）。
- **可行度**：**低（不建议）**。
- **建议**：**放弃 ctext**（我们已有二十四史全文 `texts` 3933 卷，重叠度高）。若确需其白话/英文对照，走机构订阅或改用公版替代（见 §5/§6）。

## 5. Wikisource（维基文库）宋元学案 / 明儒学案 —— 公版师承文本

- **URL**：https://zh.wikisource.org/ · MediaWiki API https://zh.wikisource.org/w/api.php
  - 宋元学案：https://zh.wikisource.org/wiki/宋元學案 （pageid 125690，**分卷 001–100**）
  - 明儒学案：https://zh.wikisource.org/wiki/明儒學案 （pageid 8317，含附案）
- **许可**：**公有领域（原书清代）+ Wikisource CC BY-SA 4.0**（页面贡献）。
- **数据格式**：MediaWiki wikitext / HTML / 纯文本，API 全量可取。
- **规模**：宋元学案 ~100 卷、明儒学案 ~62 卷；搜索"宋元學案"命中 56,127 条（含讨论/其他页）。
- **可否程序化获取**：**可以，已验证**：
  ```bash
  # 目录
  curl 'https://zh.wikisource.org/w/api.php?action=parse&page=宋元學案&prop=wikitext&format=json'
  # 单卷（卷一 安定學案）
  curl 'https://zh.wikisource.org/w/api.php?action=parse&page=宋元學案/卷001&prop=wikitext&format=json'
  ```
  内容形如"安定學案表 … 胡瑗 → 程頤 / 范純仁 / 徐積 …"——**学案表即"学者—门人"关系**，结构规整。
- **关联键**：**人物姓名**（`persons.name`），学案表列出"师"与"门人/讲友/学子"，可直接生成师承边。
- **可补内容**：学派归属 + 师承/讲友关系（补我们仅 6,612 条的 `lineage`；并可扩 `assocs` 的"师友"类）。
- **可行度**：**高**（免费、API 稳、公版、结构清晰）。
- **建议**：写解析器遍历卷 001–100，抽取"学案名 → 学者 → 门人列表"，映射到 `persons.name` 生成师承边；宋代部分优先（与当前 `song` 库主题契合）。

## 6. CBETA 电子佛典（开放 XML）

- **URL**：GitHub 组织 https://github.com/cbeta-org （`xml-p5` / `xml-p5-2018` / `BM_u8` 等）；
  官网 https://www.cbeta.org/ ；版权 https://www.cbeta.org/copyright.php
- **许可**：**CC BY-NC-SA 4.0**（非商业、署名、相同方式共享）——与 CBDB 脚本同许可族。
- **数据格式**：TEI P5 XML（`xml-p5`，1.45 GB 仓库）/ 纯文本 BM / 电子书。
- **规模**：汉文大藏经全文（数千部、数亿字），含《高僧传》《宋高僧传》《景德传灯录》等**僧人传记**。
- **可否程序化获取**：**可以**（git clone / raw 下载，无 API 限速）。
- **关联键**：僧人名 + **CBETA 卷号**（如 `T50n2061_p0755b03` 宋高僧传）；与 DILA 的 CBETA 引证字段同源。
- **可补内容**：僧人传记/生卒（文本挖掘）、《宋高僧传》等列传。
- **可行度**：**高（下载易）**，但**需 NLP 抽取**（非结构化）。
- **建议**：作为 DILA 的"原文背靠"；先用 DILA 定位目标僧人 → 用 CBETA 卷号取原文做证据。

## 8. 古代职官数据库（如《中国历代职官别名大辞典》《中国历代职官沿革史》）

- **现状调研**：无权威、开放、可直接 API/批量获取的数字化职官沿革库。
  - 我们已有 `offices` 571,137 条 + `cbdb_OFFICE_CODES`（CBDB 官职码表）+ `category` 官制分类树——**已基本覆盖**。
  - 公开渠道多为网页/PDF（词典），或收录在订阅型古籍库内。
- **可行度**：**低**。
- **建议**：**优先用 CBDB `cbdb_OFFICE_CODES` 的别名/类别表自建**；职官"沿革时间线"暂缺可靠公开源，可后续用 CBDB `POSTED_TO_OFFICE_DATA` 的年份自算。

## 9. 科举数据库（如《中国历代登科总录》）

- **可行度**：**低**。
- **建议**：**以现有 CBDB entries 为主**，不追外部源。

## 10. 关联键总表（落地用）

| 我们的字段 | 外部源 | 外部字段 | 匹配方式 |
|---|---|---|---|
| `persons.cbdb_id` | CBDB 官方最新 SQLite | `c_personid` | 精确（同源） |
| `persons.cbdb_id` | DILA 人名库 | `SameAs → CBDB personid` | DILA A-id 桥 |
| `persons.name` + `birth/death` | Wikidata | `rdfs:label` + P569/P570 | 姓名+生卒联合消歧 |
| `persons.sources`(含 Wikidata) | Wikidata | Q-ID | 补建 Q-ID 映射表 |
| `addr_geo.name` + `first_year/last_year` | CHGIS/TGAZ | `name` + `years` | 汉字+年份，取时序版本 |
| `addr_geo.chgis`(整数) | CHGIS | TGAZ `hvd_<id>` 去前缀 | **已存在，直接复用** |
| `lineage` / `assocs`(师友) | Wikisource 学案表 | 学者→门人 | 姓名映射 |
| 僧侣字段 | DILA + CBETA | 宗派/师徒/CBETA 卷号 | DILA 桥+卷号 |

## 11. 落地优先级建议（不改代码，仅调研结论）

1. **P0｜CHGIS/TGAZ**：补 `addr_geo` 坐标（现存 15,558，目标 ≥3 万条宋代地名），关联键最干净、已验证 API。
2. **P0｜CBDB 官方最新库**：`cbdb_sqlite`（HuggingFace latest.zip，139 MB）同源升级，零匹配成本。
3. **P1｜Wikidata SPARQL**：为 40 万已有"Wikidata"来源者补 Q-ID + 生卒精确日；做生卒纠错。
4. **P1｜Wikisource 学案**：抽师承边，扩 `lineage`（6,612 → 预计 2–5 千条新增）。
